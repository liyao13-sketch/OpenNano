# 内网部署（团队共用一台服务器）

> **适用场景（owner 2026-09-15 定）**：**各自笔记本连一台内网服务器** —— 每台笔记本只开浏览器，
> 数据、账号、经验记忆都在服务器上那一份。目标是"**一个团队共享一套记忆，且不互相覆盖**"。
>
> 单人本地怎么用：什么都不用配，照旧 `uvicorn main:app` 即可（`OPENNANO_AUTH` 默认 `auto`，
> **没建账号就不锁门**）。本文只讲**团队部署**。

---

## 一、三分钟起服务

```bash
# 1) 前端构建一次（服务器上只需要这一次）
cd OpenNano/web && npm install && npx vite build      # 产出 web/dist/

# 2) 起后端（关键：--host 0.0.0.0 让同事能连；OPENNANO_AUTH=on 强制登录）
cd ../server
OPENNANO_AUTH=on .venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
```

前端**由后端托管**（`main.py` 末尾自动挂 `web/dist`）⇒ 同事直接用浏览器打开：

```
http://<服务器内网IP>:8000
```

> 为什么必须由后端托管：会话 cookie 是 `SameSite=Lax`，**只有同源**才会随请求发送。
> 若前端另起端口（`vite dev` 那种），cookie 不会带上，表现为"登录了却还是未登录"。
> 开发时无所谓 —— `web/vite.config.ts` 里 `/api` 已代理到 8000，浏览器看到的仍是同源。

## 二、第一次开机：**没有默认账号，也没有默认口令**

打开页面会直接进入「Create the first administrator」：

1. 填用户名 / 显示名 / 口令（≥ 6 位）⇒ 建出**唯一的管理员**；
2. 之后所有人**没有自助注册**：由管理员在右上角用户名 → 「Team」里加号；
3. 加号时选角色：`member`（能用）/ `admin`（能管账号）。

⚠️ 这套东西**故意不设出厂口令**：有默认口令的部署等于没有身份，而且一定会被扫。

## 三、它会替你守住什么（P0 的三层）

| 层 | 解决的问题 | 行为 |
|---|---|---|
| **身份** | "这是谁" | cookie 会话；停用账号**立刻**失效（含已登录的会话） |
| **留痕** | "谁改了什么" | 所有写请求落 `~/.opennano/audit.log`（**append-only JSONL**）；建号/停用/工程保存与覆盖另有语义摘要 |
| **可撤销** | "换了口令，旧会话还在用" | 令牌里签了**会话版本号**：改口令 / 改角色 / 停用 ⇒ 版本 +1 ⇒ **旧 cookie 当场失效**（A3 审计后补） |
| **版本守卫** | "谁在我之前改过" | 工程：载入时拿 `_rev`，保存时带回来；**对不上 ⇒ 409，不保存**，界面会问你是否确认覆盖（覆盖会留痕）。库文件：盘上被改过就**拒写**（`POST /api/library/reload` 显式接受对方版本） |

**留痕在界面哪里看**：右上角用户名 → Team 面板 → Activity log（全员可看）。

## 四、环境变量（都可覆盖，见 `server/opennano_config.py`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `OPENNANO_AUTH` | `auto` | `on` 强制登录（**团队部署用这个**）· `off` 关闭强制 · `auto` 有账号才强制 |
| `OPENNANO_ACCOUNTS` | `~/.opennano/users.json` | 账号库（0600；口令只存 PBKDF2 哈希 + 每人独立 salt） |
| `OPENNANO_SERVER_SECRET` | `~/.opennano/.server_secret` | 会话令牌签名密钥（0600，**别进 git**） |
| `OPENNANO_AUDIT` | `~/.opennano/audit.log` | 操作留痕 |
| `OPENNANO_PROJECTS_DIR` | `~/.opennano/projects` | 画布工程目录（**共享的是它**） |
| `OPENNANO_DB` | `~/.opennano/opennano.db` | 知识库 |
| `OPENNANO_WEB_DIST` | `../web/dist` | 前端产物目录 |
| `OPENNANO_PBKDF2_ITERS` | `200000` | 口令迭代数（测试会调小；老账号记着自己的迭代数，调大不影响它们） |

## 四之二、并发与原子性（一台服务器多人同时写时靠它）

审计（2026-09-15，A3）实测出三处同源缺陷，修法也是同一处 —— **锁内重读 → 校验 → 修改 → 临时文件 + fsync → 原子替换**：

| 症状（修前实测） | 现在 |
|---|---|
| 两个并发建号 ⇒ **100/100 轮丢一个**（后写整份覆盖先写） | `engine/atomic.py` 的跨进程 `flock` + 锁内重读：并发建号两条都留下 |
| 两个并发 `setup` ⇒ **30/30 轮双 200**，文件里只剩一个管理员 | 判空与建号在**同一把锁内**：恰好一个 200、一个 409 |
| 提交"新口令 + 非法角色" ⇒ **返回 400 但口令已经改了** | 一次校验、一次落盘：失败则一个字节都不写 |
| 两个 worker 首次生成签名密钥 ⇒ 各写一份，**跨 worker 会话随机失效** | `O_CREAT\|O_EXCL` 独占创建：后到者读对方那份 |
| 密钥文件不是合法 hex ⇒ **登录/初始化 500** | 隔离留档（`.corrupt-<ts>`）+ 轮换新密钥 + 记 audit + **页面顶部报出**（既有的会话全部失效，需重新登录） |

⚠️ 两个仍然成立的边界：

1. **跨进程锁后端**：POSIX 上是 `flock`（`auth.lock_backend()` 可查）。没有 `fcntl` 的平台退化为
   "仅进程内锁 + 原子替换" —— 那时**只保证不写坏，不保证不丢并发改动**。
2. **登录没有限速**（A3 审计提过，本期未做）：未知用户名已改为跑同量级 PBKDF2（修掉 15.8× 的**时序枚举**），
   但**暴力猜口令**仍不受限。要挡它得上反代限速或加令牌桶 —— 已列入下一期。

## 五、⚠️ 诚实的边界（先读这一节再吹给同事听）

1. **`OPENNANO_AUTH=auto` 且还没建账号时，服务是全开的** —— 启动时会打醒目告警，`/api/auth/state` 也带 `open_to_network`，界面会把它顶到「问题」面板。**团队部署第一件事就是建管理员。**
2. **内网 HTTP 下口令是明文过网的**。这套东西防的是"**记错人 / 互相覆盖 / 事后说不清**"，
   **不防**能抓包的攻击者。要真防：上 TLS（反代加证书）或只在可信内网跑。
2. **`OPENNANO_AUTH=auto` 且还没建账号时，服务是敞开的**（这是刻意的：不让单人本地被门挡在外面）。
   所以团队部署**第一件事**就是把 `OPENNANO_AUTH=on` 设上并建管理员。界面上没建账号时会出告警。
3. **闸只拦"没见过的名字"**：机台口径那道闸拦不住"已登记但填错"的机台号 —— 归属正确性靠原始记录与证据图
   （数据线 2026-09-14 写进 `core_schema.validate_tool_ids` 旁的同一条边界）。
4. **服务器成了单点**：数据都在那台机器上。请给它配好备份（本项目至今**异盘备份仍缺**，是最该补的一环）。
5. **`--workers` 请先别开 >1**：库是整份覆盖写的，多进程下内存副本会互相打架（版本守卫会拒写，
   但用户体验是"老是冲突"）。要横向扩展得先把库改成 append-only（P1）。

## 六、备份与恢复

```bash
# 要备的就是这几个（都是小文件，除了 library.json 约 90 KB）
~/.opennano/{users.json,audit.log,library.json,opennano.db,projects/}
```

- 服务端**每次保存库文件前**会与载入时的指纹比对，**发现别人改过就拒写**（不会静默覆盖）；
- 账号文件读不动时**拒绝初始化/写入**（不会用空账号库把全组身份顶掉）；
- `audit.log` 只追加，**不要手工编辑**（要留档就整份复制）。
